# Plan Hygiene

Plan filenames are `verb-target` kebab-case — `add-dark-mode-toggle`,
`fix-login-redirect`. Before committing, rename any plan still carrying an
auto-generated slug (`precious-knitting-tulip.md`) or whose purpose drifted
after creation. A stale name is a defect; do not commit around it.

## Plans index merge driver

`docs/plans/index.html` is generated by `docs/plans/build-index.sh`, which the
`plan-agent` rebuild hook runs on every plan write. Every plan-adding branch
regenerates it, so concurrent plan PRs always conflict there.

`scripts/merge-plans-index.mjs` (registered as `plans-index` via
`.gitattributes`, activated by `scripts/setup-merge-driver.sh`, which the
SessionStart hook runs) unions the gallery cards from both sides: ours keep
their order, new cards from theirs append, and a card deleted on either side
relative to the merge base stays deleted.

The driver deliberately does **not** re-run `build-index.sh`. At merge-driver
time git has not yet written the incoming branch's plan files to the working
tree, so regenerating from disk would silently drop every incoming plan.
Ordering and timestamp drift after a driver merge is cosmetic and self-heals on
the next plan write.

Never hand-edit conflict markers in `index.html`. If it still conflicts, the
driver is not registered — run `bash scripts/setup-merge-driver.sh` and
re-merge, or finish the merge and run `bash docs/plans/build-index.sh` once
both sides' plan files are on disk.
