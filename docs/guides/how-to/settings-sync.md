# How do I... settings-sync

Back up and restore your Claude Code user settings through a dedicated git repo.

Install: `/plugin marketplace add shawn-sandy/agentics`, then `/plugin install settings-sync@agentics-kit`

## settings-backup

Copies your `~/.claude/` config into a backup git repo, then commits and pushes it.

- **Command** — `/settings-sync:settings-backup [repo-path]`
- **Say it instead** — "back up my Claude Code settings"
- **What happens** — Resolves the repo path from the argument, `~/.claude/settings-sync.json`, or a prompt, and the machine name from the `machine` key in that file (derived once from `hostname -s` and saved when missing). It switches the repo to this machine's own branch, `machines/<machine>`, so two machines sharing one backup repo never overwrite or block each other, then scans `settings.json`, `CLAUDE.md`, `keybindings.json`, `rules/`, `commands/`, `skills/`, `hooks/`, `agents/`, `output-styles/`, `scripts/`, and `reference/` for secrets before copying them in. Commits only when something actually changed — writing `.settings-sync-meta.json` with that commit — and pushes the machine branch on every run when a remote exists; a no-change run commits nothing and logs one line to the gitignored `.sync-log`. A first backup on a new machine creates its own branch and can no longer overwrite another machine's. Files already tracked that the ignore rules cover (a stray `__pycache__/`) are untracked, not deleted. Any repo-root entry that is neither a backup target nor a control file — a `plans/` directory left by an older version, say — is listed in the report under `Not a backup target (left in repo)`; nothing is deleted, since a hand-added entry is deliberate.
- **Watch out** — Directory copies use `--delete`, so anything removed locally disappears from the backup; in unattended routine mode a secret-scan hit is only logged to `.sync-log` and the backup proceeds. `settings.local.json` is excluded unless `includeLocalSettings` is `true`. A machine branch this clone did not create means two machines share one `machine` name — the run stops before committing and asks you to set a distinct `"machine"` in `~/.claude/settings-sync.json`; after re-cloning the backup repo on the same machine, run the `git config settings-sync.branch` command the message prints once to claim the branch again. A rejected push stops the run after its local commit: either two clones share a name, or the branch was edited elsewhere (on github.com, or from another clone), in which case run the realign command the message prints once. It never pulls or merges on its own. Upgrading from 1.2: update the plugin on every machine; each one's first 1.3.0 run pushes its own branch (with any commits a rejected 1.2 push left behind), and `master` stays as frozen 1.2 history.

## settings-restore

Pulls a backup repo and copies the saved settings back into `~/.claude/`.

- **Command** — `/settings-sync:settings-restore [repo-path-or-url]`
- **Say it instead** — "restore my Claude Code settings on this new machine"
- **What happens** — Accepts a local repo path or a clone URL (cloned to `~/.claude-settings-backup`, the bootstrap path for a fresh machine), lists the machines that have backed up to a `machines/*` branch and asks which to restore (a 1.2 repo with none restores the checked-out branch as before), checks that branch out, and shows an added / modified / unchanged / deleted preview. After you confirm, it copies into `~/.claude/`, verifies every entry, and reports any that failed. It then switches the backup clone back to this machine's own branch. The `hooks/` execute-bit check is measured against the backup: only a hook that is executable there and not locally is a `FAILED` entry, so an interpreter-run `python3 hook.py` no longer marks a correct restore INCOMPLETE. `settings.json` is merged, not copied: restore keeps this machine's `permissions` and `autoMode` (the only keys holding machine-specific home paths) and takes every other key from the backup, so you can keep two Macs in step by changing settings on one and restoring its machine on the other. A machine with no `settings.json` gets the backup's file unchanged.
- **Watch out** — Confirmation is mandatory, so it stops rather than run unattended. The restore overwrites `~/.claude/` and deletes local files missing from the backup, plaintext `http://` clone URLs require explicit approval, and restored settings only take effect after restarting Claude Code. The `settings.json` merge needs `jq` (in `/usr/bin` on macOS 15 and later); without it, or with invalid JSON on either side, that entry is skipped and the local file left untouched. Permission rules, deny rules included, never travel by restore once a machine has its own `settings.json` — installing the plugin on a new machine usually creates one, so the preview says how many of the backup's rules it will not apply. Restore never writes the `machine` key.
