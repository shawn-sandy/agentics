# Plan: Add Mandatory Completion Checklist with Report to Generated Plans

## Context

Every plan generated by the `implementation-plan` skill currently has acceptance criteria checkboxes, step todo/done chips, and status tracking — but nothing ties these together into a single visible "you're not done until all three are green" requirement. The acceptance criteria gate exists in the SKILL.md workflow (Step 8) as agent instructions, but it's invisible in the plan HTML itself. Users who implement plans outside the agent workflow (manually, via workflow prompts, or in a different session) have no visible reminder that all TODOs, acceptance criteria, and status must be finalized before the plan is truly complete.

Additionally, when items can't be completed there's no mechanism to document *what* was left undone and *why* — the plan just stays at `in-progress` with no explanation.

This change adds a **Completion Checklist** section with a **Completion Report** to every generated plan. The checklist makes the three mandatory requirements visible and trackable. The report provides a structured area to document any incomplete items with reasons.

## Changes

### 1. Add Completion Checklist and Report section to SKELETON.html

**File:** `kit/plugins/plan-agent/skills/implementation-plan/reference/SKELETON.html`

Add a new `<section>` between the Verification section and the Next Steps section with two parts:

**Part A — Completion Checklist** (three mandatory checkbox items):
- All step TODOs marked as done
- All acceptance criteria verified and checked off
- Plan status updated to `completed`

**Part B — Completion Report** (initially empty, populated during implementation/finalization):
- A `<div class="completion-report">` container with a `<dl>` (definition list) structure
- Each incomplete item gets a `<dt>` (what wasn't completed) and `<dd>` (reason/explanation)
- Initial template includes an empty placeholder with a muted "No items to report — all requirements met." message that gets replaced when the report is populated
- The report is always present in the HTML but visually collapsed/muted when empty

**HTML structure:**
```html
<section class="section-card card-completion" id="completion" aria-labelledby="h-completion">
  <h2 id="h-completion">
    <svg class="icon" aria-hidden="true"><use href="#ic-clipboard-check"/></svg>
    Completion Checklist
  </h2>
  <div class="completion-checklist" id="completion-checklist">
    <div class="completion-header">
      <span class="completion-badge" id="completion-badge">Required</span>
    </div>
    <ul class="completion-list" id="completion-list">
      <li>
        <input type="checkbox" id="cc1" disabled>
        <label for="cc1">All step TODOs marked as done</label>
      </li>
      <li>
        <input type="checkbox" id="cc2" disabled>
        <label for="cc2">All acceptance criteria verified and checked off</label>
      </li>
      <li>
        <input type="checkbox" id="cc3" disabled>
        <label for="cc3">Plan status updated to completed</label>
      </li>
    </ul>
    <div class="completion-report" id="completion-report">
      <h3 class="report-heading">Completion Report</h3>
      <p class="report-empty">No items to report — all requirements met.</p>
    </div>
  </div>
</section>
```

**CSS additions:**
- `.card-completion` — uses existing `.section-card` base styling
- `.completion-report` — subtle top border separating it from the checklist, slight top margin
- `.report-heading` — smaller heading (`.8rem`, uppercase, muted) matching the existing section subheading pattern
- `.report-empty` — italic, muted text indicating nothing to report
- `.report-list dt` — font-weight 600, color `var(--text)`
- `.report-list dd` — color `var(--muted)`, margin-left indent, margin-bottom for spacing between items
- `.report-list dt::before` — red circle indicator (`background: #dc2626`) for visual salience on incomplete items

**Sidebar nav:** Add a nav entry between Verification and Next Steps:
```html
<li><a href="#completion"><svg class="icon" aria-hidden="true"><use href="#ic-clipboard-check"/></svg> Completion</a></li>
```

**JavaScript:** The three completion checkboxes are `disabled` and auto-computed from DOM state — they are not user-interactive. JavaScript checks: (1) all `.step-card` elements have the `completed` class, (2) all `#criteria-list` checkboxes are checked, (3) `<html data-status>` and `<meta name="plan-status">` are both `completed`. A `MutationObserver` on the `data-status` attribute triggers re-evaluation when status changes. No localStorage persistence is needed since the checkboxes reflect computed truth.

### 3. Update SKILL.md Step 8 Acceptance Criteria Gate

**File:** `kit/plugins/plan-agent/skills/implementation-plan/SKILL.md`

In Step 8's "Implement now" flow (~line 161), after the existing acceptance criteria gate (lines 163-174), add a **completion checklist gate with report**:

```markdown
   **Completion checklist gate (mandatory — runs after the acceptance criteria gate):**
   1. Verify all step chips show `done` (every `.step-card` has the `completed` class). If any steps remain `todo`, list them.
   2. Verify all acceptance criteria checkboxes are checked. If any remain unchecked, list them.
   3. If both checks pass, check off all three completion checklist items (`#cc1`, `#cc2`, `#cc3`) and update status to `completed`.
   4. If any check fails, leave the corresponding completion checklist item unchecked, set status to `in-progress`, and **populate the Completion Report**:
      - Replace the `.report-empty` paragraph with a `<dl class="report-list">` element
      - For each incomplete requirement, add a `<dt>` describing what was not completed and a `<dd>` explaining why (e.g., "Step 3: Wire up auth middleware — blocked by missing OAuth credentials configuration" or "Criterion: No TypeScript errors — tsc reports 2 errors in src/auth.ts")
      - Each report entry must be specific: name the exact step or criterion, not just "some steps incomplete"
```

### 4. Update finalize-plan SKILL.md

**File:** `kit/plugins/plan-agent/skills/finalize-plan/SKILL.md`

After Step 5c (step cards), add two new sub-steps:

**5d — Completion checklist:** Check off all three completion checklist checkboxes (`#cc1`, `#cc2`, `#cc3`) by adding the `checked` attribute, matching the pattern used for acceptance criteria in 5b. If the user chose "only auto-check verified criteria" in Step 4 and some criteria remain unchecked, leave `#cc2` unchecked.

**5e — Completion report:** Populate the Completion Report based on Step 3b's findings:
- If all criteria were verified and all steps marked done: leave the `.report-empty` text as-is ("No items to report — all requirements met.")
- If any criteria were marked `unverified` and left unchecked (user chose "auto-check verified only"): replace `.report-empty` with a `<dl class="report-list">` listing each unverified criterion as a `<dt>` and the verification failure reason as a `<dd>` (e.g., "No matching file found in codebase", "tsc --noEmit exited with code 1", "Identifier not found in grep search")
- If the token-level evidence score was below 80%: add a report entry noting the evidence gap (e.g., "Implementation evidence: 3/5 tokens found — missing: `AuthProvider`, `useAuth`")
