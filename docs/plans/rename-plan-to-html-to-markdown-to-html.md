# Plan: Rename plan-to-html → markdown-to-html, bundle assets, HTML5-first rendering

## Context

The `plan-to-html` skill at
`kit/plugins/plan-interview/skills/plan-to-html/` currently:

1. Has a plan-specific name that conflicts with broader markdown-conversion
   use cases the user wants to support.
2. Caches theme CSS and JavaScript under `~/.claude/plan-to-html/` via a
   one-time `--setup` flow (SKILL.md Step 0.5). This adds a per-machine
   setup step and complicates distribution — fresh installs need `--setup`
   before the skill can run optimally, and the cache files drift from the
   spec if the plugin upgrades but `--setup` is not re-run.
3. Always prompts for a theme on interactive runs (Step 3) even though most
   users want the default.
4. Re-implements progress bars in custom JavaScript when modern HTML5
   (`<progress>` + `<details>`) covers parts of it natively.
5. Has no visual affordances beyond the progress bar — no timeline, no
   per-step status indicators, no scroll-position rail in the sidebar.

This refactor renames the skill to reflect its broader scope
(`markdown-to-html` with two render modes — plan-aware and generic doc),
bundles theme assets into the plugin tree (eliminating `--setup` entirely),
makes the default theme no-prompt, swaps custom JS for HTML5 native elements
where they cleanly replace it (`<progress>`, `<details>`), keeps the
scroll-spy IIFE (live nav tracking is a UX feature worth preserving), adds
four CSS-driven visual upgrades plus an inline-SVG section diagram, and
introduces a single-source-of-truth build script so spec and assets cannot
drift.

The skill rename is a **breaking change** to the plugin's public surface and
warrants a **MAJOR** version bump per `.claude/rules/marketplace.md`.

**Current plugin version: `1.22.1`; this plan bumps to `2.0.0`.** Known
external callers of `/plan-interview:plan-to-html` will receive a
skill-not-found error at 2.0.0 with no alias provided; they must update their
invocations manually. Internal callers are updated in Step 16. Doc-mode
targets users who want plan + generic markdown rendering inside Claude Code
without leaving the session to invoke an external tool (Pandoc, mdconvert).

## Objective

Rename `plan-to-html` to `markdown-to-html`, bundle theme CSS and JavaScript
inside the skill (no per-machine setup), render in auto-detected plan-mode
or doc-mode, use HTML5 native elements where they reduce custom code, add
CSS-driven visuals (step timeline, status chips, sidebar scroll rail, inline
SVG section diagram), and introduce a build script that keeps `assets/`
deterministically in sync with the spec.

0. **Add `## Security and Encoding` section to `reference/html-spec.md`**
   specifying per-sink encoding rules. *Why:* every generated HTML file is an
   XSS vector without this specification (OWASP A03:2021 / CWE-79). *Verify:*
   `grep -c "Security and Encoding" reference/html-spec.md` returns 1.
   - Body text, headings, step text → HTML-entity encode `& < > " '`
   - Attribute values (`aria-label`, `title`, `class`, `id`) → attribute-encode
   - SVG `<text>` nodes and SVG attributes → entity-encode
   - Markdown link URLs → allow only `http`, `https`, `mailto`, `#`-fragments;
     reject `javascript:`, `data:text/html`, `vbscript:`, `file:` (drop link,
     keep label text as encoded text)
   - Image URLs → allow `http`, `https`, `data:image/(png|jpeg|gif|svg+xml|webp)`
   - Code blocks → `<pre><code>` with entity-encoded content; no HTML passthrough
   - Raw HTML in markdown → escaped as literal text, not passed through

   `skip-link`, and `step-label`; each returns ≥ 1.

      section. Driven by the same scroll-spy IIFE that updates `.active`

      height` and writes `--scroll-progress: 47%` to `<nav>` as a CSS
      custom property; `.scroll-rail::before { height:
      var(--scroll-progress); }`. Hidden on mobile via existing sidebar
      collapse rule.

      `<main>` > `<article>`, embed using `aria-labelledby` + `<title>` for
      maximum AT compatibility (SC 1.1.1 — `aria-label`-only SVG has
      inconsistent support in older JAWS/NVDA combinations):
      `<svg role="img" aria-labelledby="section-diagram-title">
      <title id="section-diagram-title">Plan sections: {comma-separated

      - Connector between adjacent nodes: `<line x1 y1=20 x2 y2=20
        stroke="var(--color-accent)" stroke-width="1.5"/>`.
