How the check worked — and why it's careful

  • All local. Data came from usage counters in ~/.claude.json, ~50 recent session transcripts, and the settings cascade. The only outbound request attempted was the version lookup (denied).
  • Read-only first, then one confirmation. Every check ran without side effects and produced a full report before a single change was proposed — applied only after an explicit "clean up everything."
  • Untrusted by default. Transcript content and harvested names (server names, paths, commands) were counted but never spliced into shell commands — the settings write used a temp-file jq merge with the server name passed as a quoted argument, and secret-bearing config was read key-by-key, never dumped.
  • Signal honesty. A 1.4-day window is dense (50 sessions) but calendar-thin; where the data couldn't justify a verdict — the maintainer's own plugins — the call was to keep and say so, not to guess.
