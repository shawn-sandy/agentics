Why

The team was sharing Claude Code configuration by hand-copying files out of one person's home directory — no versioning, no updates, no way to know what changed. Since this repo already runs a plugin marketplace, the shareable pieces were packaged as a plugin: semver, a changelog, and a one-command install.

What shipped

ComponentWhat it does
ts-commenterAgent — TypeScript/JSDoc documentation specialist, optimized for AI-assistant comprehension. Auto-discovered on install.

sync-rulesSkill — installs the bundled team rules into ~/.claude/rules/. Diffs first, reports a sync plan, and asks per file before overwriting anything. Never touches rules it doesn't ship.

Bundled rules: plan-mode.md (plus the plan skeleton), component-driven-ui.md, typescript-jsdoc.md, and review-bot-loops.md.

Decisions a reviewer should know

Rules travel inside the skill, not as a plugin component. Claude Code plugins have no native "rules" type (only commands, skills, agents, hooks), so the rule files ship as the sync-rules skill's payload and are copied into place on demand — with confirmation, since the destination holds each person's own rules too.

The payload lives at skills/sync-rules/rules/, not top-level rules/. The dist builder's KEEP allowlist was silently dropping a top-level rules/ directory (5 files gone from the published build). Nesting under skills/ ships everything with zero build-script changes.
