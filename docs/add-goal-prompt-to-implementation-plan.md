## How it works

The goal prompt is wired through the same three surfaces as the implement and workflow prompts: a `<meta>` tag, a visible/collapsible row in the body, and a Step 2 placeholder computed from the plan's objective.

**Skeleton change** (`SKELETON.html`): a `<meta name="plan-goal" content="{goal-prompt}">` tag is inserted into `<head>` alongside the existing `plan-implement` and `plan-workflow` meta tags. In the body, a `.plan-goal` `<details>` block sits between the implement (green) and workflow (blue) rows with a purple accent (`--purple*` CSS tokens). It contains a `<code id="goal-cmd">` element and a Copy button calling `copyGoal(this)` — exactly mirroring the implement and workflow clipboard helpers. CSS hides the block when `data-status="completed"` and suppresses it in print.

**Skill contract change** (`SKILL.md`): Step 2 now always computes `{goal-prompt}` — no flag, no complexity heuristic — from the condensed objective, plan path, and the canonical digest-extraction one-liner (the same clause used in the implement prompt, so the pursuing agent reads the spec digest rather than the full ~21k styled HTML). Step 3 always writes the `plan-goal` meta tag into the rendered HTML, and the HTML Output Requirements section lists `plan-goal` among always-present tags.

**Smoke test** (`test-goal-prompt.sh`): six assertions verify that the meta tag is present, the `.plan-goal` markup carries the correct IDs and onclick, the CSS block exists, print-hide is in place, DOM order is `implement → goal → workflow`, and SKILL.md documents `{goal-prompt}`. The three sibling skeleton tests (`test-plan-digest.sh`, `test-save-pdf.sh`, `test-responsive-retrofit.sh`) were verified to still pass after the change — no regression.

A later change (v2.x, `#488`) extended the goal prompt to fan out in parallel across multiple plan-objective variants, but the core structure — always-present, no-flag, outcome-framing — has not changed since 2.6.0.

## How to use it

The goal prompt is automatic — every plan generated by `/plan-agent:implementation-plan` includes it. No invocation flag is needed.

The purple "Pursue as goal" disclosure appears below the green "Implement" row and above the blue "Run as workflow" row. Click Copy to get the outcome-framing prompt for pasting into a new session or a workflow invocation.
