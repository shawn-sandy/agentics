## How it works

Every HTML plan generated by `implementation-plan` is rendered from `reference/SKELETON.html`. The skeleton is the single authoritative template: any prompt element that needs to appear in all future plans must live there. Before this change, the skeleton rendered two execution framings — an implement prompt (step-by-step, in-session execution) and a conditional workflow prompt (parallel subagent orchestration). The goal prompt is a third, always-present framing.

The `{goal-prompt}` placeholder is computed in Step 2 of the SKILL.md contract, unconditionally — no flag and no complexity heuristic gates it. The contract fills it from the plan's objective and path using the same digest-extraction one-liner that the implement and workflow prompts use. Step 3 then always emits `<meta name="plan-goal" content="{goal-prompt}">` in the HTML `<head>`, regardless of plan type.

In the rendered body, the `.plan-goal` `<details>` element sits between the green implement row and the blue workflow block. It uses the purple design token family (`--purple`, `--purple-bg`, `--purple-border`) to distinguish it visually. Inside the block, a `<code id="goal-cmd">` element holds the prompt text; an `onclick="copyGoal(this)"` attribute wires it to the clipboard helper function defined in the skeleton's `<script>` block.

The CSS rules for `.plan-goal` include a hidden state when the plan is completed (`[data-status="completed"] .plan-goal { display: none; }`) and print suppression, matching the behavior of the implement and workflow blocks.

The six assertions in `test-goal-prompt.sh` verify: the `plan-goal` meta tag exists in the skeleton, the `.plan-goal` markup is present with `id="goal-cmd"` and `onclick="copyGoal(this)"`, the `.plan-goal` CSS block exists, `copyGoal` is defined as a function, DOM order places the goal block after implement and before workflow, and the SKILL.md contract mentions `{goal-prompt}`, `plan-goal`, and `copyGoal(this)`.

## How to use it

The goal prompt requires no user action — it appears automatically in every plan generated by `/plan-agent:implementation-plan`. Open a generated HTML plan and expand the purple "Pursue as goal" disclosure row to copy the outcome-driven prompt. Use it when you want the implementer to have latitude to find a better path to the same result rather than execute the steps mechanically.
