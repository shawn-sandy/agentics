## How it works

Close the plan-completion gap from both ends: make every prompt that starts an implementation require the plan be checked off, and add a PostToolUse hook that deterministically catches a plan whose steps and criteria are all checked while its `status` still says otherwise — then unlock `finalize-plan` so the model can act on that signal.

Plans generated by `plan-agent` routinely finish implementation and never get marked `completed`. The gallery then misrepresents what shipped. The completion machinery is not missing — it is unreachable. Verified in the current tree:
