Failure paths — nothing resolves silently
Three ways a lane run goes wrong, and what the lead does for each
Lead processes a completed lane
Merge conflict
On a disjoint-ownership plan a conflict is a plan bug, not noise.
Stop. Name the two lanes and the file. Ask: resolve by hand, or fix the lanes and re-run.
Never auto-resolved outside the repo's registered merge drivers.
Failed lane
Worker died, a Verify: failed, or the report says blocked. Three choices:
Re-dispatch — delete the lane branch, fork fresh from the current plan branch. Never resume state the report flagged.
Run in lead — the main session takes the lane's steps sequentially.
Stop — every other lane's merged work is kept.
Ownership violation
The audit finds a diff path outside the lane's owns:.
Refuse the merge. Name the file and the lane. The LANE REPORT is self-reported — the audit is what makes the boundary real.
Checked before every merge: git diff --name-only vs owns.
