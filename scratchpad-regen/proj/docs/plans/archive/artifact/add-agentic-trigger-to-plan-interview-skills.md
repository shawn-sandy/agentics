# Plan: Add "agentic" as a trigger keyword across plan-interview skills

> The plan filename `review-the-triggers-to-quiet-orbit.md` was autogenerated
> and is non-descriptive per `.claude/rules/plan-hygiene.md`. Rename to
> `add-agentic-trigger-to-plan-interview-skills.md` as the **first
> implementation step** (see Step 0 below).

## Context

The last fix on this branch (commit `52434fd`, v1.14.2) made the
`plan-interview` skill trigger on "stress test" (space) in addition to
"stress-test". The user now wants the plugin's triggers reviewed holistically
and wants the word "agentic" added as an activation keyword so natural
phrasings like "stress test my agentic plan", "check my agentic plan status",
or "document this agentic plan" reliably match.

Today, no skill or command in `kit/plugins/plan-interview/` mentions
"agentic" functionally — the word appears only in the repo URL
(`shawn-sandy/agentics`) and the marketplace name (`agentics-kit`). Adding
"agentic" expands trigger coverage without breaking any existing phrasing.

Per prior clarification, the change applies to **all four** skills
(`plan-interview`, `deep-grill`, `plan-status`, `documenting-plans`), the
marketplace tags, the plugin keywords, and the README trigger examples.

### Step 1 — Add "agentic" to the four skill descriptions

Each skill keeps its existing trigger keywords and gains one additional
phrasing that surfaces the word "agentic". Keep the language concise —
the goal is a matcher hint, not a rewrite.

1. `kit/plugins/plan-interview/skills/plan-interview/SKILL.md` (lines 3–8)

   Append `, including agentic plans and agentic workflows,` into the
   existing sentence so the final description reads:

   ```yaml
   description:
     Use when the user asks to stress-test, stress test, interview, validate,
     critique, pressure-test, or find gaps and risks in an implementation
     plan — including agentic plans and agentic workflows — with phrasings
     like "stress test this plan", "stress test plan", "stress test my
     agentic plan", "interview my plan", or "stress-test the plan". Does
     not execute the plan or apply fixes.
   ```

2. `kit/plugins/plan-interview/skills/deep-grill/SKILL.md` (lines 3–6)

   ```yaml
   description:
     Use when the user asks to deep grill a plan, walk through each decision
     branch, examine design-tree branches, or stress-test individual
     decisions in an implementation plan — including agentic plans and
     agentic workflows (e.g., "deep grill my agentic plan").
   ```

3. `kit/plugins/plan-interview/skills/plan-status/SKILL.md` (line 3)

   Extend the existing sentence to mention agentic plans without weakening
   the "not for stress-testing" exclusion clause:

   ```yaml
   description: Use when the user asks to check, update, or determine the
     status of a plan file (including agentic plans), when entering or
     exiting plan mode, when creating or updating plans, or when working
     with plan files in any capacity — not for stress-testing, validating,
     or critiquing plan content.
   ```

4. `kit/plugins/plan-interview/skills/documenting-plans/SKILL.md` (lines 2–5)

   Insert "(including agentic plans)" after "completed plan file" and add
   one example phrasing:

   ```yaml
   description: Use when the user asks to generate, write, produce, or
     publish developer-facing documentation from a completed plan file
     (including agentic plans) — or asks to "document a plan", "turn a
     plan into docs", "write docs for this plan", "document my agentic
     plan", or "create a reference doc from this plan". Synthesizes a prose
     document at docs/<slug>.md from three sources: the plan body, live
     code inspection of every cited file path, and a scoped git history
     window. Does not check or update plan status (use plan-status for
     that), does not stress-test or critique the plan (use plan-interview),
     and does not rename plan files (use review-rename-plans).
   ```
