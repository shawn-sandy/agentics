# Plan Maintenance

Archive completed plans as browsable HTML, generate a directory index, and
surface variant/duplicate files for cleanup. Sub-workflows run with user
confirmation gates between each.

## Instructions

### Step 0 — Parse flags and create progress todos

Check `$ARGUMENTS` for flags:

- `--archive` — run the archive sub-workflow
- `--index` — run the index sub-workflow
- `--variants` — run the variant review sub-workflow
- `--all` — run all three in order: variants → archive → index
- `--background` — when combined with `--archive` or `--all`, spawn the
  rendering loop as a background agent

If no flag is provided, default to `--all`.

Resolve the plans directory using the same priority as `update-plan-status`:

1. **Settings `plansDirectory`**: Read the `"plansDirectory"` key following
   Claude Code's settings precedence — project-local `.claude/settings.local.json`,
   then project `.claude/settings.json`, then global `~/.claude/settings.json`.
   Use the first that sets it.
2. **Default fallback**: Use `${PWD}/docs/plans/`.

Use `TodoWrite` to create a todo for each active sub-workflow. Mark each
`status: "completed"` as you finish it.

### Sub-workflow A: Variant review (`--variants`)

**When `--all` is active, this runs first** — consolidate before archiving.

#### A.1 — Detect variant patterns

Glob all `*.md` and `*.html` files in the plans directory. Scan filenames for:

- **Suffix variants:** files ending with `-alt`, `-revised`, `-v\d+` (e.g.,
  `-v2`, `-v2.3`), or `-review.html`
- **Semantic clusters:** group files by their first 3+ hyphenated words. If
  two or more files share the same prefix, flag them as a cluster. Example:
  `make-deep-grill-default-yes.md` and `make-deep-grill-optional.md` share
  the prefix `make-deep-grill`.

#### A.2 — Present clusters

For each cluster, output:

```
Cluster: "make-deep-grill" (3 files)
  1. make-deep-grill-default-yes.md      status: completed  created: 2026-03-10
  2. make-deep-grill-optional.md          status: completed  created: 2026-03-12
  3. promote-deep-grill-to-mandatory.md   status: completed  created: 2026-03-15

  Recommendation: keep #3 (most recent completed), archive #1 and #2
```

For `.html` review artifacts with no matching plan purpose:

```
Orphan artifact: add-rejection-remediation-prompt-review.html
  Recommendation: delete (review artifact, not a source plan)
```

#### A.3 — Get user approval per cluster

Ask via `AskUserQuestion` for each cluster:

> "How would you like to handle this cluster?"

Options:
- "Apply recommendation" — keep the canonical file, archive/delete the rest
- "Skip" — leave all files as-is
- "Review individually" — ask about each file in the cluster

For "Apply recommendation":
- Files recommended for archiving: `git rm` them (they are variant duplicates;
  the canonical file remains)
- Files recommended for deletion (`.html` artifacts): `git rm`

#### A.4 — Commit

If any files were removed:

```
git add -A <plansDir>/ && git commit -m "chore(plans): consolidate N variant plan files"
```

Where `<plansDir>` is the resolved plans directory from Step 0.

If no changes were made, skip the commit silently.

### Sub-workflow B: Archive (`--archive`)

**When `--all` is active, this runs second** — after variant consolidation.

#### B.1 — Identify archive candidates

Glob all `*.md` files in the plans directory. Read frontmatter for each.
A file is an archive candidate if ALL of these are true:

- `status: completed`
- Most recent date (`modified` if present, otherwise `created`) is 30+ days
  before today
- File is not `README.md`

Also check if a reference doc exists at `docs/<slug>.md` (generated by the
`documenting-plans` skill). This is informational — not a requirement for
archiving.

#### B.2 — Present candidates table

```
Archive candidates (N files, completed 30+ days ago):

 #  File                                  Type     Created     Has Doc
──  ────────────────────────────────────  ───────  ──────────  ───────
 1  add-allowed-tools-recommendation.md   feature  2026-03-26  yes
 2  create-skill-reviewer-plugin.md       feature  2026-02-10  yes
 3  fix-login-redirect.md                 fix      2026-01-15  no
 4  document-plugin-version-bump.md       docs     2026-03-01  yes
...

Target folders:
  features/   12 files
  fixes/       5 files
  refactors/   3 files
  docs/        4 files
  chores/      6 files
  general/     2 files (no type field)
```

Ask via `AskUserQuestion`:

> "Archive N plans as HTML to docs/archive/<type>/? Source .md files will be
> git rm'd (git history preserves originals)."

Options:
- "Archive all" — process every candidate
- "Exclude some" — review and deselect specific files
- "Cancel"

#### B.3 — Render and archive

Determine whether to run foreground or background based on `--background` flag.

**Foreground (default):**

For each candidate:

1. Determine target folder from `type` field. The archive root is always
   `docs/archive/` (a project-level documentation artifact, independent of
   `<plansDir>`):
   - `feature` → `docs/archive/features/`
   - `fix` → `docs/archive/fixes/`
   - `refactor` → `docs/archive/refactors/`
   - `docs` → `docs/archive/docs/`
   - `chore` → `docs/archive/chores/`
   - missing/unknown → `docs/archive/general/`
2. `mkdir -p` the target folder
3. Invoke the `markdown-to-html` skill with `--mode=plan` on the source file.
   The skill writes `<slug>.html` next to the source `.md` in the plans
   directory.
4. `mv <plansDir>/<slug>.html docs/archive/<type>/<slug>.html`
5. `git rm <plansDir>/<slug>.md`
6. If a matching `-review.html` exists, move it to the same type folder.
7. Output progress: `"Archived 12/33: <slug>.html → docs/archive/features/"`

**Commit safety:** Stage all changes incrementally but defer the final commit
until ALL files are processed. If any render fails mid-batch:

- Report the error and list which files succeeded vs. failed
- Tell the user they can `git checkout -- .` to undo all staged changes
- Do NOT commit partial results

On full success:

```
git add -A <plansDir>/ docs/archive/ && git commit -m "chore(plans): archive N completed plans as HTML"
```

**Background (with `--background` flag):**

Spawn a background `Agent` with the full candidate list and rendering
instructions. The agent:

1. Performs the same render-move-rm loop as foreground
2. Commits on success
3. If `--all` was active, also runs Sub-workflow C (Index) after the commit,
   since index depends on the archive being complete

The parent session continues immediately after spawning.

---

### Sub-workflow C: Index (`--index`)

**When `--all` is active, this runs last** — after archiving, so counts are
accurate.

#### C.1 — Scan active plans

Glob `*.md` files in the plans directory (exclude `README.md`). Read
frontmatter from each. Group by status:

1. `in-progress` — currently active work
2. `todo` — planned but not started
3. `draft` — early ideas
4. `completed` — done but not yet archived (< 30 days old)

#### C.2 — Scan archived plans

Check if `docs/archive/` exists. If so, count `.html` files in each type
subdirectory (`features/`, `fixes/`, `refactors/`, `docs/`, `chores/`,
`general/`).

#### C.3 — Generate README

Write `<plansDir>/README.md` with the following structure. Compute relative
links from `<plansDir>` to `docs/archive/` so they resolve correctly
regardless of where the plans directory is configured:

```markdown
<!-- auto-generated by plan-maintenance — do not edit manually -->

# Plans

Last updated: YYYY-MM-DD

## Active Plans

### In Progress (N)

| Plan | Type | Created |
|------|------|---------|
| [add-dark-mode-toggle](add-dark-mode-toggle.md) | feature | 2026-05-10 |
| [fix-auth-redirect](fix-auth-redirect.md) | fix | 2026-05-12 |

### Todo (N)

| Plan | Type | Created |
|------|------|---------|
| ... | ... | ... |

### Draft (N)

| Plan | Type | Created |
|------|------|---------|
| ... | ... | ... |

### Recently Completed (N)

Plans completed within the last 30 days — not yet archived.

| Plan | Type | Created |
|------|------|---------|
| ... | ... | ... |

## Archived Plans

N plans archived as browsable HTML in [`docs/archive/`](../archive/).

| Category | Count |
|----------|-------|
| [Features](../archive/features/) | 12 |
| [Fixes](../archive/fixes/) | 5 |
| [Refactors](../archive/refactors/) | 3 |
| [Docs](../archive/docs/) | 4 |
| [Chores](../archive/chores/) | 6 |
| [General](../archive/general/) | 2 |
```

Omit any status section that has zero files. Omit the Archived section if
`docs/archive/` does not exist or is empty. Omit type rows with zero count.

#### C.4 — Commit

```
git add <plansDir>/README.md && git commit -m "docs(plans): regenerate plans index"
```

## Examples

```
/plan-interview:plan-maintenance                     # runs --all (variants → archive → index)
/plan-interview:plan-maintenance --archive           # archive only
/plan-interview:plan-maintenance --index             # regenerate index only
/plan-interview:plan-maintenance --variants          # variant review only
/plan-interview:plan-maintenance --all --background  # full cycle, rendering in background
/plan-interview:plan-maintenance --archive --background  # archive in background
```
