# plans-library

Build the plans gallery and open it in the browser.

The gallery is generated by `hooks/build-index.sh` — the same script the
`rebuild-plans-index.py` PostToolUse hook runs after every plan write, and the same
collection rule `build-artifacts-index.sh` uses for its Plans tab count. This skill does
not reimplement the scan, the sort, the card markup, or the tab counts.

A second implementation is how this skill's gallery and the hook's gallery drifted apart:
it used to run `find "$PLANS_DIR" -maxdepth 1 -name "*.html"`, which sees only the top
level of the plans directory. That does keep `archive/` and `artifacts/` out — but it also
drops every plan filed in any other subdirectory, so a plan the hook rendered a card for
vanished the moment a user ran this skill. `build-index.sh` walks the tree and excludes
`archive/` and `artifacts/` by name, which is the rule the rest of the plugin already uses.

---

## Exit plan mode

**If in plan mode**, call `ExitPlanMode` first — this workflow mutates state.

## Step 1 — Build and write the gallery

```bash
plan-agent-plans-index
```

Invoke it by bare name — the plugin's `bin/` is on the Bash tool's PATH. Do not spell the
path to `hooks/build-index.sh` through a plugin-root variable instead: the Bash tool
refuses any command text carrying a shell expansion, before permission rules are even
consulted, so that shape never runs for anyone.

The script resolves `plansDirectory` (project-local → project → user-global, falling back
to `docs/plans`), collects every `.html` under it except `index.html` — walking
subdirectories, skipping `archive/` and `artifacts/` — orders in-progress plans first and
then newest-first by `plan-created`, and writes `index.html` from the shared
`plans-gallery.html` template.

On success it prints one line to stdout:

```
[build-index] wrote <PLANS_DIR>/index.html (<N> items, <YYYY-MM-DD HH:MM>)
```

Capture `<PLANS_DIR>/index.html` as `INDEX_PATH` and `<N>` as `PLAN_COUNT`. `<N>` is the
number of cards the script actually wrote, not the number of files it found — anything it
could not open is already excluded, so Step 2 compares like with like.

If no `wrote` line appears, the script skipped the build and explained why on stderr —
the plans directory is missing, no plan files were found in it, or the plugin templates
could not be located. Relay that message and **STOP**. For a missing or empty directory,
tell the user:

> "No HTML plans found in `<PLANS_DIR>`. Run `/plan-agent:implementation-plan` to create your first plan."

Saved artifacts have their own gallery at `docs/artifacts/`, built by
`build-artifacts-index.sh`; they are excluded here by design.

## Step 2 — Verify the index

Confirm the file is complete and carries one card per plan the script counted.

```bash
python3 - "$INDEX_PATH" "$PLAN_COUNT" <<'EOF'
import sys
from html.parser import HTMLParser

path, expected = sys.argv[1], int(sys.argv[2])
html = open(path, encoding='utf-8').read()

class Counter(HTMLParser):
    cards = 0
    def handle_starttag(self, tag, attrs):
        if tag == 'a' and 'gallery-card' in dict(attrs).get('class', '').split():
            self.cards += 1

c = Counter()
c.feed(html)
if not html.rstrip().endswith('</html>'):
    sys.exit(f"TRUNCATED: {path} does not end with </html>")
print(f"OK: {c.cards} cards from {expected} plans" if c.cards == expected
      else f"MISMATCH: index has {c.cards} cards but {expected} plans were counted")
sys.exit(0 if c.cards == expected else 1)
EOF
```

If the command exits non-zero, report the failure — naming the index path, the card count,
and the `PLAN_COUNT` the script reported — and **STOP** instead of opening the gallery.

## Step 3 — Open in browser

```bash
open "$INDEX_PATH" 2>/dev/null || xdg-open "$INDEX_PATH" 2>/dev/null || echo "[plans-library] no browser launcher"
```

A headless box has neither launcher, and the gallery is still written and still
valid — so this never fails the skill. It reports instead: the fallback `echo`
is what tells you which of the two messages below to use.

If the `no browser launcher` line appeared, tell the user:

> "Plans library generated at `<INDEX_PATH>` with {PLAN_COUNT} plans. No browser launcher available here — open the file yourself to view it."

Otherwise:

> "Plans library generated at `<INDEX_PATH>` with {PLAN_COUNT} plans — opened in your browser. Click any card to open it."

## Step 4 — Stop

**STOP.** Do not run git commands or invoke other skills after delivering the gallery.
